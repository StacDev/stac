The Stac State Scope gives part of a screen its own state. The variables in `state` are created when the widget is first built and live as long as it does. Widgets inside read them by name, `setValue` actions inside write to them, and widgets that read a variable rebuild when it changes.

See [State](/concepts/state) for how state works across screens and the app.

## Properties

| Property | Type                   | Description                                                                 |
|----------|------------------------|-----------------------------------------------------------------------------|
| state    | `Map<String, dynamic>` | The variables this scope declares, with their initial values. Values can be [expressions](/concepts/expressions), evaluated once when the scope is created. |
| child    | `StacWidget`           | The widget that can read and write the state.                               |

## Initial Values From Other State

Initial values can read the state around the scope. They are evaluated once, when the scope is created:

```json
{
  "type": "stateScope",
  "state": {
    "draft": "{{$app.user.name ?? ''}}",
    "editing": false
  },
  "child": { "type": "text", "data": "Editing {{draft}}" }
}
```

## Nested Scopes

Scopes can be nested. A name is read from the innermost scope that declares it, and a `setValue` entry writes to the innermost scope that declares its first name. Names no scope declares are read from, and written to, the screen.
